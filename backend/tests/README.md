# Backend test database strategy

The ordinary pytest suite uses offline contract fixtures and fake services. It must not connect to the shared development database, require Ollama, or download models.

The corrected harness verified the persistence draft against a fresh disposable PostgreSQL 16/pgvector container on 1 November 2026. Upgrade, repeated upgrade, downgrade to base, and re-upgrade passed. Five database tests passed for same-organization foreign keys, job lifecycle and failure-message rules, demo seed behavior, document/chunk/job persistence, 384-dimensional vector round-trip, and rejection of a 383-dimensional vector. A separate offline wrapped-exception regression also passed; it verifies SQLAlchemy adapter extraction without a database. The vector test checks the public.embeddings.embedding catalog type is vector(384), casts the input as an untyped vector, and requires the native asyncpg DataError with SQLSTATE 22000. Two earlier harness attempts stopped before migrations on readiness and shell-formatting issues; their resources were cleaned up. The successful run's disposable container, network, volume and sanitized source copy were also removed; no shared database was accessed.

The one-off harness and test module are retained outside this repository at /tmp/knexus-pgverify-review-20261101/verify_disposable_pg.sh and /tmp/knexus-pgverify-review-20261101/test_persistence_postgres.py. The harness uses the existing local pgvector/pgvector:pg16 image with pulls disabled, synthetic credentials, a fresh uniquely labeled named volume, and a fresh dedicated bridge network. The database container is the only network attachment; the host port is published only on 127.0.0.1. A non-internal bridge is required for Docker to publish the runtime port, so the disposable database container can make outbound connections. It contains synthetic data only and is removed after the run.

For every future database test, use a fresh disposable database and volume; never use the shared KNEXUS database, Compose service or persistent volume. Pass the exact synthetic URL only to the test process. Before connecting, verify the URL, loopback host, database name, database user, and the values of current_database() and current_user. Keep cleanup limited to resources created by that run. Do not use prune commands or docker compose down -v.

alembic -c alembic.ini upgrade head --sql renders SQL offline and does not connect. Offline model or contract checks do not prove that PostgreSQL enforces the constraints. Run the canonical contract checker separately from persistence tests. The settings file path is anchored to the repository root, and exported environment variables override .env values. Keep ordinary tests database-free.
